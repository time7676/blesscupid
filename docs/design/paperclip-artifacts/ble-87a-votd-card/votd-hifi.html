Locale source (BLE-144)

Pattern
No per-card toggle. Card renders in the active app locale only.
Source of truth
App locale from i18n.resolvedLanguage (BLE-46). User changes it in Settings → Language.
Default
id (Bahasa) → TB2/TB. en → NIV.
What flips
verse text, reference, translation tag, eyebrow copy (Hari ini ↔ Today) — footer constant.
Persistence
Owned by i18n layer (AsyncStorage["app:locale"]); not by the card.
Why removed
BLE-144 — dual-language UI made screens longer with low impact; one screen, one language.

5 · Acceptance (mirrors issue)

  • Tag rendered correctly: verse data with translation: "TB2" renders Mazmur 37:5 (TB2); "TB" renders (TB); "NIV" renders (NIV). Never (placeholder).
  • Footer present on every variant: home, profile-preview, modal-preview — copy verbatim, stone-500 at 11px (10px on compact).
  • Single-locale render (BLE-144): card renders only the active app locale (id ⇒ TB2/TB; en ⇒ NIV). No per-card toggle, no dual-language stacking.
  • Locale source: reads from i18n layer (BLE-46). Changing locale in Settings re-renders the card on next focus.
  • Contrast: gold-700 on gold-100 = 5.84:1 · AA pass for normal & large text. stone-500 on gold-100 = 4.62:1 · AA pass.
  • No regression on the BLE-87 frame: gold-100 ground, gold-500 left rule, Source Serif 4 22/32 body — preserved.

6 · Notes

  1. BLE-144: the per-card EN/ID pill toggle was removed. CEO direction: one locale at a time, switcher lives in Settings only. Translation code still appears as the parenthetical tag in the reference line — that is the literal provenance signal.
  2. Footer is non-link by design. Pastor wanted humility, not click-bait to a licensing page. If legal later asks for a link, escalate before changing — copy stays plain text in v1.
  3. Hairline divider above the footer is gold-700 @ 18% so it reads as part of the gold ground, not a foreign UI line. Avoid border-color: var(--border-subtle) here — too cool against the warm ground.
  4. Compact and modal variants share the same DOM contract — engineering wires one component, CSS modifiers handle the rest. Verse content is selected upstream by the i18n layer based on app locale.
