Pastor mode — 24h transcript seal on revoke

When the audited user revokes pastor-mode, the mentor's reading must end. Within 24h the Pastor's admin transitions from "Berjalan bersama" to "Sudah selesai" — transcripts become inaccessible (403), Pastor's own notes survive in a read-only journal that no longer links back to the user's chat stream, and after 90 days the transcript hard-deletes unless legal hold is set. Audited user keeps her mirror permanently — the seal is asymmetric.

Why the journal exists

The Pastor's reflection-work is part of HIS spiritual labor. Deleting it on Maya's revoke would punish him for her healthy choice. Preserving it teaches the opposite: ending a walk is a good event for both walkers, and the mentor gets to keep the lessons.

  • Pastor's notes are kept indefinitely. They survive transcript hard-delete (90d) because they are a different actor's data.
  • Single-column serif body. Frames the surface as a personal journal, not as a chat record.
  • Marked "ditulis ketika perjalanan masih berjalan". Provenance is visible — these were not written after the fact.
  • No link back to Maya's chat stream. The seal is one-way.
  • No "kirim catatan baru" button. Notes about Maya are closed; Maya is not a thread anymore.
  • No read-receipt revealed post-seal. Whether Maya read or not is no longer Pastor's information.
"Bersyukurlah dalam segala hal" — termasuk dalam berakhirnya hal-hal yang baik. 1 Tesalonika 5:18 · TB2

What the API enforces

Behind the surface is a small set of server contracts. The hi-fi is the visible half; the spec doc pastor-seal-spec.md in this folder is the other half.

  • seal_after = revoked_at + 24h. Job runs hourly, idempotent, picks up everything past its seal_after.
  • 403 on transcript reads when relationship.state ∈ {"sealed","hard_deleted"} and actor = pastor.
  • Notes survive seal. pastor_notes.audited_user_id is replaced with audited_user_snapshot (display_name, avatar_color, walked_for_days).
  • hard_delete_after = revoked_at + 90d. Cron drops transcript rows. Pastor notes untouched. Skipped if legal_hold = true.
  • Audited user's mirror is unaffected. Maya keeps her record permanently — that surface lives in user-side schema, not pastor-side.

From revoke to hard-delete · 90 days

Seal timeline at a glance

Four discrete states. The Pastor's view shifts at T+24h; transcript bytes leave the database at T+90d unless legal hold. Maya's mirror is unaffected throughout.

T = 0

User revokes

Maya taps "Ya, akhiri" (BLE-108 surface 5a → 5b). relationship.state = "revoked". Pastor receives gentle in-app notice; sidebar entry already shows "Sudah berakhir" pill.

T + ≤24h

Seal job runs

Hourly cron: relationships where state = "revoked" and revoked_at ≤ now − 24h → state = "sealed". Pastor's transcript reads start returning 403. Notes get the user_snapshot copy and move into journal queries.

T + 90d

Hard delete

Daily cron: sealed relationships past 90d with legal_hold = false → transcript rows dropped (messages, read receipts, attachments). Pastor notes untouched. Pastor sidebar entry stays as journal pointer.

Indefinite

Maya's mirror persists

Surface 6 (BLE-108) lives in user-side schema and is never touched by these jobs. Maya keeps the record of what was read, when, by whom — for as long as she wants it.
